# v0.2.0：综述质量门禁与公开发布说明

## 解决的问题

旧版本将所有论文当成原创实验研究，要求固定数量的实验条件、实验结果和带单位数值。叙述性综述即使正确提取了分类框架、共识、争议和研究空白，也可能被“关键结果不足”拦截。本版本让文献类型同时影响提示词、结构化数据、笔记渲染与质量门禁，而不是补写无依据的实验数值来凑数。

## 文献类型如何识别

每个模型阶段的输出必须包含 `documentType`：

| 值 | 笔记中文属性 | 渲染与门禁分支 |
|---|---|---|
| `research_article` | 原创研究 | 原创研究 |
| `review` | 叙述性综述 | 综述 |
| `systematic_review` | 系统综述 | 综述 |
| `meta_analysis` | Meta分析 | 综述 |
| `perspective` | 观点与展望 | 综述 |
| `other` | 其他 | 未识别时保守采用原创研究门禁 |

优先采纳综合阶段、全文阶段、方法阶段、PDF 阶段中第一个明确的非 `other` 分类。这些阶段均未提供有效的非 `other` 分类时（包括缺失、无效或全部为 `other`），程序通过题名、摘要和期刊名称中的 review/reviews、systematic review、meta-analysis 等关键词回退识别。最后无法确定时采用原创研究门禁。

关键词判断并不等于可靠的学术分类，综述期刊也可能包含原创研究。新任务应以模型阅读主文后明确给出的类型为主；人工审核时仍需核对“文献类型”。目前没有前端文献类型手动切换器。

## 笔记结构

原创研究保留既有六章 V5 结构。综述采用：

1. 综述问题与范围：核心问题与综述贡献。
2. 检索范围与分类框架：组织逻辑、覆盖对象、比较维度与评价方法。
3. 核心观点与证据脉络：综合结论、代表性证据与原文定位，可靠图片就近嵌入。
4. 共识、争议与证据强度：主张、支撑证据与替代解释。
5. 研究空白、趋势与可复用内容：局限、未来方向与可复用比较框架。
6. 知识关联与个人笔记：研究用途、关联笔记和个人判断。

必要时追加“待核验”。中文属性、Zotero 条目键、DOI 合并机制与 `HUMAN` 标记不变；软件版本升级不改变笔记的 `文献笔记-v5` 架构标记。`templates/文献笔记模板-v5.md` 是原创研究的手工参考，自动输出以 `note-v5.mjs` 为准，不应拿原创研究章节检查综述。

## 实际运行的统一门禁

工作台创建或续跑任务时统一使用 `library` 标准；旧档位只保留函数兼容，不是界面中的可选质量级别。

| 检查 | 原创研究 | 综述家族 |
|---|---|---|
| 主章节 | 对应类型的六章齐全 | 对应类型的六章齐全 |
| 创新/贡献 | 至少 3 项 | 至少 2 项 |
| 方法 | 至少 8 项实验条件 | 至少 2 项范围/分类方法 |
| 结果 | 至少 8 项关键结果 | 综合结论数或主张数中较大的一个至少为 6；不将两者相加 |
| 带单位证据 | 有 PDF 时至少 8 个正则匹配 | 不强制凑原创实验数值 |
| 原图 | 有 PDF 但没有可靠图映射时拦截；有映射时至少嵌入 `min(可用数, 4)` | 没有可靠图映射时不因此单独拦截；存在映射时至少嵌入 1 张 |
| FTIR | 提及时要求出现峰位单位 | 不因一般性提及就要求原创峰位 |

自动门禁属于结构与数量检查，不等于人工证据审核。它不自动证明各条论点真实、峰位归属正确或覆盖全面；图片是否和描述一致、来源是否支持主张，仍需人工检查。综述不要求凑数值，但原文给出的定量比较、单位和边界条件仍应保留。

## 升级和使用

### 已有安装

1. 先停止/等待当前处理任务结束并保存，然后关闭工作台后端服务，再备份实际数据目录与 Obsidian 笔记。数据目录默认是项目内 `data/`，若设置了 `LITERATURE_WORKBENCH_DATA_DIR`，以其指定路径为准。不要将这些备份上传到 GitHub。
2. 如果目录是干净的 Git 克隆，可执行 `git pull --ff-only` 更新主分支；存在本地修改或历史不一致时不要强行覆盖。也可以下载 `v0.2.0` 源码至一个新目录。
3. 若使用新目录，可在停机状态下复制原实际数据目录到新项目的 `data/`，或通过 `LITERATURE_WORKBENCH_DATA_DIR` 指向原数据目录。两份服务不要同时写同一个数据目录。
4. 运行 `node --check server.mjs` 和 `node test-note-v5.mjs`。
5. 重新启动服务：`node server.mjs`，或使用 Windows 启动脚本；刷新页面。只刷新网页不会重新加载后台模块。
6. 新任务自动使用新分类和门禁。不会自动重写正式库、修改 Zotero 条目、改变插件或迁移笔记。

### 新用户

按 [README](../../README.md) 安装 Node.js、Python 依赖，配置自己的 Zotero、本地 Obsidian 路径和模型通道。此 Release 不附带运行环境、第三方插件、MinerU 转换服务或任何人的账号授权。

### 旧失败任务如何恢复

- 原任务确实只是门禁误判、且原有阶段结果完整：在任务卡选择“保留缓存继续”，复用结果重新生成未完成笔记。这不是绝对零调用承诺：缺失的阶段和同批次未处理的其他文献仍可能调用模型。
- 缓存仍套用实验论文逻辑、缺少范围/分类或关键综合结论：备份后选择“清除缓存重跑”。该按钮会清除该任务旧阶段结果并重新调用模型，可能覆盖生成笔记的 AI 内容；操作前查看确认提示。
- “按当前设置继续”更新模型设置，但仍保留已有阶段结果；它不等同于重跑已经完成的阶段。
- 服务另有开发者用重排接口，可仅根据缓存重建指定文献，不调用模型。一般用户无需手工调用；没有缓存时也不会凭空补齐内容。
- 一个批次的单篇修复成功不代表整个批次完成，需查看其余条目是否待处理。重建笔记不等于自动审核入库。

重新生成会保留同一草稿中指定 `HUMAN` 区块，但不是任意手改文本的自动合并器；尤其是区块外人工改写，应先备份、后比较。正式库同篇合并仍由原审核流程处理。

## 私有命名覆盖

源码不再内置任何个人条目键与题名/分类映射。若确实需要稳定的个人命名，可在实际数据目录创建 `note-overrides.json`：

```json
{
  "YOUR_ITEM_KEY": {
    "title": "你自己的中文短题名",
    "folder": "你自己的研究主题"
  }
}
```

`YOUR_ITEM_KEY` 只是占位符，使用时替换为自己的条目键。服务在启动时读取该文件；改动后需重启。默认 `data/` 被 Git 忽略，文件不得进入公开提交或 Release 附件。如果将数据目录改到其他位置，应自行确保该位置也不被版本控制。未配置覆盖时按模型建议和原元数据命名，不需要复制任何人的条目配置。

## 验证与发布边界

- `node test-note-v5.mjs` 使用合成数据覆盖原创研究、综述、旧缓存识别、缺失证据、图映射以及本地命名覆盖。
- `node scripts/check-public-release.mjs --staged` 检查 Git 暂存快照中的运行数据路径、常见凭据形式、个人目录路径和条目映射。它是启发式检查，不能替代人工审查。
- 发布只使用源码与通用文档，不包含论文 PDF、支持材料、MinerU 原文/图片、真实笔记、队列、浏览器配置、DPAPI 文件、API Key 或实际本地覆盖。
- 移除源码中的个人映射不会擦除旧提交、分叉、下载副本或缓存。本版本不改写历史；若需要清理已公开历史，应另行安排受控操作。

## 已知限制

- 四类综述家族当前共用一个分支；尚未实现系统综述 PRISMA、纳入排除完整性、偏倚风险，以及 Meta 分析效应量、置信区间、异质性等专用门禁。
- 没有可靠图片映射可能是论文无图，也可能是提取器未成功识别。本版本只取消因此对综述的硬拦截，不宣称自动配图完整。
- 分类由模型或启发式提供，仍可能错分；旧缓存的证据不足不会因更换模板被自动补齐。
- 单元测试不验证每一种模型供应商、操作系统或真实 PDF。升级后请先用一篇自己的文献做人工验收，再扩大批量。
